# Modern redesign of the AutoChannel dashboard with light and dark themes

## Problem
The React SPA in `frontend/src/` is a direct port of the old Jinja templates. Its styles came over from `static/css/sidebar.css` and only work on a dark background (see the comment at the top of `frontend/src/styles.css`), and most colors are hard-coded hex values like `#36393f`, `#999` and `#fff`. The current UI has several problems:
- Navigation is confusing. A hamburger button toggles an icon-only sidebar, and the same server icons appear twice, in both the top nav and the sidebar. Login and logout sit inside a dropdown under the username.
- The server list on `/dashboard` shows only 128px icons with no names.
- The category settings explain each field only through `title` tooltips on the table headers, and the table doesn't fit on small screens.
- Spacing, type sizes and colors are inconsistent from page to page, and there is no light mode.

## Requirements
- R1: The app supports a light theme and a dark theme. On first visit it follows the OS setting (`prefers-color-scheme`). A theme toggle on every page lets the user switch, the choice is saved in `localStorage` and restored on reload, and the page never briefly shows the wrong theme while loading.
- R2: All colors, spacing, corner radii and type sizes come from one set of CSS custom properties (design tokens) in `frontend/src/styles.css`, with a value for each theme. Components and the remaining CSS use these tokens instead of hard-coded hex colors. Body text, muted text, links, buttons and form controls meet WCAG AA contrast (4.5:1 for normal text) in both themes.
- R3: `frontend/src/components/Layout.tsx` is rebuilt as a single responsive app shell:
  - A header with the Auto-chan brand linking to `/`, links to "Servers" (`/dashboard`) and "How-To" (`/instructions`), the theme toggle, and either a "Login" link to `/login` or a user menu showing the avatar and username with a "Logout" link to `/logout`.
  - The duplicate guild icons in the top nav and the collapsing sidebar are removed.
  - At a 375px-wide viewport, all navigation can be reached and the page has no horizontal scroll.
- R4: The server list on `/dashboard` (`frontend/src/pages/Dashboard.tsx`) shows each server as a card or tile with its icon and its visible name, and the whole card links to `/dashboard/:guildId`. A user who manages no servers sees a clear empty state.
- R5: The guild categories page (`frontend/src/pages/GuildCategories.tsx` and `frontend/src/components/CategoryTable.tsx`) meets the following:
  - It shows the server's icon and name in a page header.
  - The "AutoChannel" / "Custom Channels" tabs look like a clearly selected control (segmented control or underline tabs).
  - What each setting means, including its default and its allowed range, can be seen without hovering.
  - Saving shows a busy state on the control being saved.
  - At 375px wide, every setting can be used without the page scrolling sideways.
- R6: Home, Instructions, Guild added, Not Found, the login prompt and the loading spinner in `RequireLogin.tsx`, the error alert and the "Add Auto-chan to …" invite state all use the same tokens, page-header pattern, content width and spacing scale. Toasts in `frontend/src/toasts.tsx` follow the active theme.
- R7: All interactive elements show a visible keyboard focus ring in both themes. The decorative `bounceInUp` and `hvrcenter` animations are removed or turned off under `prefers-reduced-motion`.
- R8: Behavior and accessible names stay the same:
  - Switches keep the names `"<category> enabled"` and `"<category> custom channels enabled"`.
  - Inputs keep the names `"<category> prefix"`, `"<category> channel size"`, `"<category> empty count"` and `"<category> custom prefix"`.
  - The tabs, the "Login" link, the server links named after the guild, and the "Add Auto-chan to <guild>" link keep their names.
  - API calls in `frontend/src/api.ts` are unchanged.

## Acceptance criteria
- [ ] `cd frontend && npm run typecheck && npm test && npm run build` exits 0, and all 7 tests in `src/App.test.tsx` pass without changes to their assertions. (R8)
- [ ] `cd frontend && npm run test:e2e` exits 0. The tests in `e2e/screens.e2e.ts` keep covering every screen they cover today. Text assertions may be updated only where visible copy was deliberately changed, and every accessible name listed in R8 is still asserted. (R3, R4, R5, R6, R8)
- [ ] The e2e suite saves a light and a dark screenshot of every screen into `frontend/e2e/screenshots/` (for example `home-light.png` and `home-dark.png`). A reviewer opening them sees both themes applied consistently, with no unthemed (old Discord-gray) areas. (R1, R6)
- [ ] An e2e test that emulates `colorScheme: 'dark'` finds `data-bs-theme="dark"` (or the equivalent theme attribute) on `<html>` at first paint. After the toggle is clicked and the page reloaded, the other theme is still active. (R1)
- [ ] An e2e test at a 375×812 viewport visits `/`, `/dashboard` and `/dashboard/:guildId`. It asserts that `document.documentElement.scrollWidth <= 375` and that the Servers, How-To, theme toggle and Login/Logout controls can be reached. (R3, R5)
- [ ] `grep -nE '#[0-9a-fA-F]{3,6}\b' frontend/src/components frontend/src/pages` returns nothing. In `frontend/src/styles.css`, hex values appear only inside the token definitions. (R2)
- [ ] An axe-core check (`@axe-core/playwright`) on each screen, run in both themes, reports no `color-contrast` violations. (R2)
- [ ] On the logged-in dashboard screenshot, each server tile shows its name ("Planet Express", "Mom Corp"). The guild categories screenshot shows each setting's help text and default without any hover. (R4, R5)
- [ ] Tabbing through the guild categories page shows a visible focus ring on every tab, switch, input and save button in both themes. This is checked by hand or by a screenshot taken with an element focused. (R7)

## Out of scope
- Changes to the Flask backend, the `/api/*` contracts, OAuth `/login` and `/logout`, or the database.
- New features or settings: bulk edit, per-category reordering, search, i18n.
- Swapping Bootstrap for another CSS framework or component library, or adding Tailwind.
- New branding: logo or illustrations beyond restyling the existing `/img/*` assets.
- Pixel-diff visual regression baselines and CI changes in `.github/workflows/ci.yml`.
- Rewriting the Home and Instructions copy, beyond small wording fixes needed for the new layout.

## Open questions
- Should we keep Bootstrap 5.3 and theme it through `data-bs-theme` plus custom properties (the proposed default), or does the reviewer want to drop Bootstrap entirely?
- Should we keep Poppins from Google Fonts or switch to a system font stack? A system stack removes the external request and the font-swap flash.
- Is there a preferred accent color? The proposal keeps a Discord-adjacent blurple (close to the current `#7386d5`) and adjusts it so it passes AA contrast in both themes.
- On narrow screens, should category settings become stacked per-category cards (the proposed option) or stay a table that scrolls horizontally inside its container?
- Can `@axe-core/playwright` be added as a dev dependency for the contrast check, or should contrast be checked by hand from the screenshots?
